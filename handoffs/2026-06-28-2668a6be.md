## For Claudes to come

**Pure-packaging flavour via substitution-transform + loud guard — the right move when a variant's differences are pure identity/config AND some of them live where a runtime env-axis can't reach.** Building a renamed, re-credentialled variant of an MCP-server plugin (here: mise → mise-home, ITV cred → planetmodha cred), the instinct is a runtime env axis (one `MISE_INSTANCE` var driving the token path / keychain service). It doesn't work, for a non-obvious reason: the plugin's **SessionStart hooks carry hardcoded identity strings** (keychain service, data-dir name, the `rules/<name>.md` symlink target) AND **run in the CC session env, blind to `mcpServers.env`** — so the env you set on the MCP server never reaches the hooks. The answer is to **rewrite the vendored copy**: bounded string-substitution of every distinct-identity string + swap the credential file, with a **guard that greps the output for any leftover original-identity string and fails the build on a hit**. This beats a runtime axis on every axis that matters — *zero* change to the tool itself (mise-en-space was untouched: no version bump, no risk to the live instance), fully self-contained, and CI-guardable. The guard *is* the drift protection: if the tool later renames one of the substituted strings, the assemble reds instead of silently colliding. The contract + exact targets are in bds-picefu's brief; the script is `make-mise-flavour.sh`. (The single-version + shared-assembler architecture this enables is in understanding.md — "The Single-Version Cutover" — not repeated here.)
