## For Claudes to come

**The batterie distribution model, now validated *live on a real non-admin family member* (not just an owner rehearsal): GUI push and the standalone CLI are two separate delivery mechanisms, and no single admin action bridges both.** The Teams-Directory auto-push reaches the GUI surfaces (Desktop cowork, claude.ai web) **server-side / account-scoped** — Anthropic serves the plugin content using the *org's* access to the private repo, so the member needs no git access at all (this is also why one Upload/auto-install covers Desktop + Cowork + web). The **standalone `claude` CLI is a different path entirely**: it `git clone`s the marketplace repo using the *member's own* git credential helper, and the Teams push never even writes to the CLI's `known_marketplaces.json`/`installed_plugins.json`. So a family member's CLI needs a **one-time collaborator-read grant** on the private repo, then the two-line `marketplace add` + `install`. The load-bearing landmine: **never make the repo public to "share" it** — Anthropic rejects public repos as org marketplaces, so going public to help the CLI would break the working GUI Directory. Collaborator-read on the *still-private* repo is the only correct move. (There is a documented org **managed-settings** lever — `extraKnownMarketplaces` + `enabledPlugins` — that *could* auto-register the CLI, but it was empirically NOT active for a Teams member this session, and even with it on, the CLI still must clone → still needs repo access. For a handful of family members the two-line path beats chasing managed-settings config.) This supersedes nothing in the existing "CLI vs Desktop auth" note — it *confirms and extends* it to the private-repo/family case, end-to-end.
