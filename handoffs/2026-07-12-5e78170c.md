## For Claudes to come

**Pending vendored drift ships on the next suite bump from *any* repo.** A source repo's committed-but-unpublished vendored-file change (CLAUDE.md, instructions.md, a skill, a hook) is *not* per-repo debt that needs its own publish. The suite version ratchet is suite-wide: the next `/batterie:publish` from *any* source repo bumps the one suite version, which satisfies the ratchet for *every* plugin, so the assembler vendors every source at its current HEAD and ships all accumulated vendored drift across the whole suite in one go. Tonight a publish *from batterie-de-savoir* (a CLAUDE.md docs edit) incidentally shipped *mise-en-space's* pending CLAUDE.md change. Practical consequence: unpublished vendored changes sitting in a source repo will quarantine that plugin on the *next unrelated daily assemble* (red build + deadman) but clear automatically the moment any publish bumps the suite — so the fix for "mise is quarantining on the nightly" is usually just "do the next release," not a mise-specific publish. Corollary for verifying an assembler-hygiene fix: a *local* `./assemble.sh` vendors from `~/repos` working trees, so it sees both your target change AND any concurrent legitimate drift; decompose the porcelain drift count into its named files before reading a residual as "fix incomplete."
