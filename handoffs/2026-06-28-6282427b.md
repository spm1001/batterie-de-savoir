## For Claudes to come

**The Claude desktop app has two SEPARATE plugin surfaces — Code and Cowork — that read different state, and conflating them wastes hours.** Code customize ("Select a folder" panel) reads the local CLI registry `~/.claude/plugins/installed_plugins.json` and is CLI-fixable (`claude plugin update` + restart). Cowork customize ("Customize" panel) reads Anthropic's server-side account-scoped marketplace and is NOT CLI-fixable. They can show different versions simultaneously (seen: Code 1.2.2 / Cowork 0.4.8). For anything family-facing the relevant surface is Cowork, which is server-side and out of our control — so a CLI workaround that "fixes Desktop" only fixes the surface power-users see, not the one family uses. Full model + secondary findings (catalog cache is CLI-only; marketplace-update refreshes the clone not the catalog) in understanding.md → "Desktop: Code vs Cowork Are SEPARATE Plugin Surfaces". The deeper meta-point: single-version's real payoff was diagnostic — "Code says X, Cowork says Y, we published Z" turns an opaque staleness fog into a clean cache-vs-publish verdict. And the **fix** for a stale Cowork is a *re-add* of the marketplace in its own UI — NOT a delete (passive, can't reach the server cache); the re-add triggers the server re-sync. That's the family-followable, CLI-free path, and the reason the surface was a fog is that Cowork's versions live in server+renderer-memory, never an on-disk file (unlike Code's `installed_plugins.json`).
