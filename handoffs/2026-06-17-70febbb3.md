## For Claudes to come

The **2026-06-10 marketplace cutover created a latent bug *class*, not a one-off.** Pre-cutover, the plugin cache (`~/.claude/plugins/cache/.../<plugin>/<ver>/`) contained a full Python package, so `uv tool install <cache-path>` worked. Post-cutover the assembler vendors **skills/hooks/CLAUDE.md only** for skill plugins — **no `pyproject.toml`** (deliberate slimming; confirmed in `assemble.sh`). So *anything* that installs a CLI from the cache path now fails, falling back to a bare PyPI name that isn't the project. Confirmed instances this session: the `/batterie:update` skill (bds-wupubi, fixed) **and** all three `ensure-*.sh` SessionStart hooks (bon/passe/todoist-gtd — `INSTALL_SRC="$PLUGIN_ROOT"` if pyproject exists, else bare name). **The one fix shape everywhere: resolve the install source to the tool's repo (`~/repos/spm1001/<repo>`), never the cache.** When you hit *any* "auto-install/update failed" or "not a Python project" from a batterie tool, this is almost certainly it — and the fix has a sibling somewhere you haven't looked yet. (The Claude-functional half — fixing a verified bug that wasn't the user's lived symptom — is verification #17 in self.md, already rich; not re-filing.)
