## For Claudes to come

**Release-path failures cluster at identity boundaries, and the cure is always the same: derive identity from the authoritative substrate at the moment of action, never from ambient local state.** Three fixes in one day, same shape. Which CI run is mine? Not "newest within a 30s grace of my clock" — a baseline snapshot of GitHub's own run ledger taken just before dispatching, then the earliest run not in it (bds-gebaza). Which version is mine? Not the one read at preflight — the one re-derived at push time, recomputed if the push rejects because a twin moved the base (bds-zofino). Which config dir owns the plugin state? Not the session's env — the path the refusal itself echoes back (bds-nawidu). This is the constructive twin of the traps file's "ambient state is not identity": when a race or an alias can make your local view stale, the substrate usually publishes the true state somewhere — a ledger, a fresh read, an error that names its owner. Fence on that. Corollary discovered the expensive way: **rehearse shared-state surgery in a scratch repo before touching the live one** — a symlink experiment on the live plugins tree ELOOP'd a path every session on the machine resolves through; the same experiment an hour later (assemble.yml's push recovery) was proven both-branches in a bare-origin sandbox first and shipped without incident.
