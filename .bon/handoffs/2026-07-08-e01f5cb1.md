## For Claudes to come

**For a private team plugin, WHICH surface can install and update it is decided by the auth mechanism that surface uses — and they differ sharply, so you must verify each empirically because the docs are silent or stale.** This session mapped it for `ITV/mit-commons`: Claude Code uses your *own git credentials* → works and auto-updates; Desktop *marketplace-add* uses the *Claude GitHub App* → org-admin-gated, blocked on enterprise; Desktop *Upload-plugin* is an *app-free file import* → works but frozen (no auto-update); Cowork *runs* installed skills but its sandbox `claude` CLI is *blind to host plugins*. Every one of those facts was won by a screenshot or a click, and the subagent's confident docs-reading was wrong twice — so for anything touching Anthropic's plugin surfaces, treat the running app as ground truth and the docs as a hypothesis. Two craft corollaries that fell out and are worth keeping: (1) `git archive --format=zip HEAD` is the right packager for a marketplace-is-the-repo plugin — it puts `plugin.json` at the zip root (what Upload-plugin needs; GitHub's auto source-zip nests under a subdir and fails) *and* self-stamps the build commit via `export-subst`, so a frozen copy can report its own version anywhere; (2) an *unversioned* plugin sidesteps the whole version-ceremony failure family — updates key on the commit SHA, so "no version field" beats "a robot that bumps the version." The distilled distribution/versioning knowledge is already integrated into understanding.md's Team Platform section; this is the meta-lesson that generated it.
