## For Claudes to come

**Two-layer hygiene for GitHub Actions: separate generation-time from maintenance-time.** When an LLM writes new workflow YAML, training data is stale by the time it reaches a user — `actions/checkout@v3` lands in 2026 instead of `@v6`. Simon Willison's `https://simonw.github.io/actions-latest/versions.txt` is the public list of current major versions for the official `actions/*` namespace; fetching it before generating workflow YAML solves the staleness problem at the moment it matters. Dependabot solves SHA-level drift *post-generation*, but only if the Python (`uv`) ecosystem is explicitly enabled in `.github/dependabot.yml` — the default GitHub config covers vulnerability *alerts* without the auto-PR job, so security alerts arrive without anything fixing them and you accumulate stale deps invisibly. The full pattern, top-to-bottom: Simon's list at write-time → manual SHA pin at commit-time → Dependabot weekly-grouped at maintenance-time. Three problems, three mechanisms. Each layer alone leaves a gap; together they make manual security catch-up sessions unnecessary. The hidden corollary: the SHA-pin convention (`uses: org/action@<sha> # vN`) creates a comment whose role is purely human — the SHA is what runs, the comment is what reminds you which major you're on. When a maintainer doesn't ship a rolling major-version tag (e.g. astral-sh/setup-uv currently has v8.0.0 and v8.1.0 but no rolling `@v8`), the comment becomes aspirational; Dependabot will rewrite it to a specific patch on next bump. Not a bug, just an asymmetry across maintainers worth knowing.

**Plongeurs together: opportunistic side-cleanup is first-class work, not scope creep.** When you spot consistency drift across a suite during otherwise-narrow work — e.g. one repo's Dependabot config differs from the rest, or one workflow file's comment style is off — the marginal cost of fixing all of it *while you have the context* is much lower than the cost of remembering to come back. "We try to keep batterie consistent" is licence to do all 10 instead of just the one you started in. The decision rule: if the cleanup is mechanical (cp this canonical file across N repos), do all N; if it requires judgement per-repo, file a bon and stop. The shape from this session — five batches of identical canonical YAML, three rebases, ten clean commits — is what "doing all N" looks like when it's right.
