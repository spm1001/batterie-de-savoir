## For Claudes to come

**Two distribution surfaces, opposite repo-visibility requirements — and you can't satisfy both with one repo.** Claude org/Teams Directory marketplaces require a **private or internal** GitHub repo (their server-side Cowork sync rejects public repos: *"Only private and internal repositories can be used for marketplaces"*). The **public CLI** path (`claude plugin marketplace add`) and the personal Desktop "Add marketplace" path require a **public** repo. `spm1001/batterie` is deliberately public (chosen for ITV/CLI reach), so the Teams Directory is simply unavailable — and "internal" isn't an option because `spm1001` is a personal GitHub account, not an Org/Enterprise. The trap that round-tripped before it was written down: flipping the repo private to "make Teams work" silently breaks the CLI/personal path everyone actually uses. Now documented in CLAUDE.md "Repo visibility".

**Claude Desktop loads plugins from Anthropic's server-side marketplace, NOT the local `~/.claude/plugins/cache` the CLI reads — they are separate codepaths with separate update mechanisms.** This is why a CLI can be fully current (git-cloned, fresh) while Desktop shows a *frozen server-cached snapshot* (e.g. a pre-cutover version + a since-deleted plugin), and why local file checks can't diagnose a Desktop staleness. When debugging "Desktop shows the wrong version," the relevant state is server-side (and largely unseeable); the tells are in `~/Library/Logs/Claude/claude.ai-web.log` + `main.log` (look for `fetchAccountScopedRemotePlugins`, marketplace `/sync` errors). Remove+reinstall re-fetches the same server cache, so it isn't a fix.

**Suite version model:** the `batterie` plugin's own version IS the human-facing suite version (Debian-style) — set it at milestones; per-plugin versions stay independent so each plugin's "update available" signal only fires when that plugin actually changes. Surfaced via `/batterie:version` (the canonical "what am I on?" since Desktop's view is unreliable) and a banner atop `/batterie:update`.

**The cutover CLI-install bug class (now fixed everywhere known):** post-2026-06-10, the marketplace vendors skills/hooks/CLAUDE.md only for skill plugins — no `pyproject.toml`. So any code that installs a CLI from the plugin cache path fails, and the bare PyPI name is not a fallback (none of these CLIs are published to PyPI). The one correct shape everywhere: install from the source repo — local `~/repos/spm1001/<repo>` if present, else `'<pkg>[extras] @ git+https://github.com/spm1001/<repo>'` (PEP 508, extras before the `@`).
