The architectural direction for the marketplace is "better assembly, not monorepo." Source repos stay separate (bon, trousse, passe, etc.) for clean git history and independent development. The published marketplace should converge to a single repo — spm1001/batterie — that works for both CLI and Desktop. CLI currently uses batterie-de-savoir with `source: url`; Desktop uses spm1001/batterie with physical copies via assemble.sh. The bridge is assembly automation: assemble.sh copies .claude-plugin/, skills/, hooks/, commands/ from each source repo into plugins/<name>/. The lint (scripts/batterie-lint.py) can run post-assembly to catch drift before it ships. The key unsolved problem: making assembly reliable enough to be CI-automated rather than manually triggered. The mise/ gitignore issue (bds-susezi) is one instance of this class of problem.

Also established this session: commands/ is legacy, skills/ is preferred. Both are loaded identically by Claude Code — same frontmatter, same backtick-bang, same runtime. The only difference is skills/ supports references/ and scripts/ subdirectories. Batterie's /batterie-update was converted to /batterie:update using the skills format.

Gueridon was removed from the marketplace — it's infrastructure (Node.js web UI), not a Claude capability. 8 plugins remain in the CLI marketplace.
